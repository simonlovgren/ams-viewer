# Ad view requirements (AD)

| ID | Requirement | Priority | Status | Notes |
|---|---|---|---|---|
| AD-001 | An ad shall be presented as close as possible to a real job ad, not as a table or JSON. | Must | Implemented | Hero header, formatted description, side panels. |
| AD-002 | The header shall show title, employer, logo (with fallback) and colored tags. | Must | Implemented | Logo loaded from remote URL. |
| AD-003 | The description shall be formatted with paragraphs, headings and lists where detectable. | Should | Implemented | Heuristic, from plain text. |
| AD-004 | The ad shall show key facts: publication and last application date, employment, hours, duration, salary, vacancies, workplace, driving licence, experience. | Must | Implemented | |
| AD-005 | The ad shall show requirements and nice-to-have items (skills, languages, experience, education). | Should | Implemented | |
| AD-006 | The ad shall show how to apply, contacts and employer details. | Should | Implemented | |
| AD-007 | An external application page link shall open in the system browser (http/https only). | Should | Implemented | |
| AD-008 | Tags and breadcrumb items shall apply the corresponding filter and go to the list. | Should | Implemented | |
| AD-009 | Ad text shall be rendered safely (escaped; no HTML from source). | Must | Implemented | |
| AD-010 | Employer logos shall be cached when first downloaded. Caching happens dynamically during use (when an ad is viewed), not during import. The cache shall be stored in the same location as the database (the `AMS Viewer` data folder). | Should | Planned | Not started. Today logos are loaded straight from `logo_url` on every view. See docs/tasks.md. |
| AD-011 | The ad view shall provide case-insensitive free-text search across displayed ad content, highlight every match, and allow cycling through matches while bringing the current match into view. Find controls shall be aligned at the right side of the breadcrumb bar. | Should | Implemented | D29: `/` focuses in-ad find outside editable controls (NAV-008); D32: right-align controls and shrink the input when the ad pane is narrow. Browser layout verified at 960x600 and 1400x900; real Electron interaction not manually tested. |
| AD-012 | The ad title header shall provide a page-icon source-data button opening an in-window source view with vertically stacked, pretty-printed, syntax-highlighted JSON panels for stored source data and enrichment additions only. The enrichment panel shall be hidden when no additions exist. Visible panels shall match the ad header width and ad styling. Breadcrumbs shall append `source`, with the ad title linking back to the rendered ad; the Back button and all other Back actions shall return to that ad. Find in Ad shall remain functional across visible JSON panels, including highlighting, match cycling, `/` focus and shortcut help. | Must | Implemented | D60. Source means stored, pruned JSON, not the original file record including empty/null fields. Enrichment means additions to the detail projection, not the complete enriched ad. Regression tests, eight browser theme/font/size cases and disposable native IPC/button/find/breadcrumb Back passed; physical native keyboard/mouse buttons not manually tested. |
