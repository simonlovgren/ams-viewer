# UI requirements (UI)

| ID | Requirement | Priority | Status | Notes |
|---|---|---|---|---|
| UI-001 | The application shall have a modern, sleek UI. | Must | Implemented | Not yet visually reviewed. |
| UI-002 | The application shall default to ams-dark and support selectable themes, including ams-light. | Must | Implemented | D51-D54/T19 complete: Appearance name button opens built-in/custom chooser; selection is immediate and retained before splash/main paint. Browser workflows and native DOM-driven selection/restart pass. |
| UI-003 | The built-in themes shall favor teal, blue, purple and pink accents, with shades suitable for their dark or light surfaces. | Must | Implemented | D51/D52: ams-dark preserved; ams-light uses neutral light surfaces with darker semantic accents. Contrast regression checks pass. Browser checks cover both themes, sizes/fonts and all views; light Search/Ad screenshots reviewed. Semantic tag colors remain governed by UI-004/LST-002. |
| UI-004 | Related information (location, occupation levels, etc.) shall be distinguishable by consistent tag colors. | Must | Implemented | See LST-002. |
| UI-005 | Updates shall not reload the page or reset the user's context. | Must | Implemented | |
| UI-006 | The window shall have a minimum usable size. | Could | Implemented | 960x600. |
| UI-007 | The filter sidebar shall be resizable in width, with its current width as the minimum. Its sections, titles and inputs shall not overlap at the minimum width or window size. | Should | Implemented | D27: non-shrinking sections scroll instead of overlapping. Browser fixture verified at 310 px, 960x600 and 1400x900, in both font modes; drag resizing and chart redraw passed. |
| UI-008 | The filter sidebar shall be collapsible and expandable so the list can use the full width. | Should | Implemented | D35: independent icon toggle with accessible expanded state and saved preference. Browser keyboard and responsive-layout checks passed; native Electron interaction not manually tested. |
| UI-009 | The main menu shall be collapsible to icons only, and shall be collapsed by default. | Should | Implemented | Toggle at the bottom of the menu (labels get tooltips); state saved. Not seen in the UI. |
| UI-010 | Every filter widget shall be vertically resizable by dragging its bottom divider. Widget heights shall be remembered independently across restarts and retained through collapse and Clear all. | Should | Implemented | D34: shared bottom dividers, pointer capture, keyboard resizing and independent localStorage heights. All 18 renderer tests and browser drag, keyboard, reload, collapse, Clear all and layout checks passed at 960x600 and 1400x900 in both fonts. Native Electron interaction and quit/relaunch not manually tested. |
| UI-011 | The filter widgets, including the ads-over-time chart, in the filter sidebar and the statistics widgets in the statistics bar shall each be collapsible and expandable by pressing their title, using a mouse or keyboard. Collapsed state shall persist across restarts; collapsed filter widgets shall indicate active selections. | Should | Implemented | D27, D35: shared helper now covers six filter widgets and two statistics shells. Renderer tests and browser title activation, reload persistence and active-filter badges passed. Actual Electron quit/relaunch persistence not manually tested. |
| UI-012 | The UI shall use monospace font(s) to give it the feel of a data inspection tool. | Should | Implemented | D26: all main-window text, including headings and ad descriptions, uses an offline system monospace stack by default. Browser fixture layout checked at 960x600 and 1400x900; Electron startup verified. |
| UI-013 | The search view shall have a statistics bar on its right-hand side for statistics widgets other than the ads-over-time chart, which shall stay in the filter column beside the time filters. The bar itself shall be collapsible, and each statistics widget shall be collapsible (UI-011). | Should | Implemented | D35: 280 px right column; T9/SRC-020 supplies Top employers. Geography has no placeholder until T5/SRC-019 is implemented. Renderer and browser resize, collapse, persistence and layout checks passed; Electron startup passed. Native interactions not manually tested. |
| UI-014 | While the application starts and loads its data, a splash screen with a loading progress bar shall be shown, so it is clear that the application is starting. | Must | Implemented | Frameless splash window with stage text, percentage and elapsed time; closes when the main window has its first results. Layout not seen by the agent (window opened, not viewed). |
| UI-015 | Large ad counts in the UI shall use compact, human-readable notation, with exact counts available on hover. | Must | Implemented | D25: shared compact formatter (e.g. 12.5k, 11.3M); exact hover values in filters, totals, chart and import counts. Boundary tests and Electron startup verified; visual layout not reviewed. |
| UI-016 | Settings shall provide a monospace on/off option that applies immediately to all main-window text and persists across application restarts; monospace shall be enabled by default. | Must | Implemented | D26: Settings > Appearance slider-style switch; localStorage settings object. Unit tests and browser reload verified; actual Electron quit/relaunch preference retention not manually tested. |
| UI-017 | Each hierarchical filter box (occupation and location) shall provide a small text button labelled "collapse all" directly below its search field, usable by mouse or keyboard, that collapses every level in that tree without changing active filter selections or the other tree. | Must | Implemented | D30: text controls inside widget bodies, distinct from title-based widget collapse; clear only the target tree's search text and saved expansions. Renderer tests and earlier browser fixture click/Enter/Space, selection retention and reload persistence passed. Revised text/placement, non-overlap, collapse and hiding with the widget verified at 960x600; native Electron interaction not manually tested. |
| UI-018 | Application popup messages and confirmation queries shall use in-app modal dialogs matching the keyboard-shortcut help style instead of native alert/confirm popups. Removing a data source shall require explicit confirmation; Cancel or Escape shall leave it unchanged. Dialogs shall contain focus, block background navigation and restore focus on dismissal; destructive confirmations shall initially focus Cancel. | Must | Implemented | D33: shared dialog shell for shortcut help, source-removal confirmation and failure messages. Renderer tests and browser fixture interactions/layout passed at 960x600 and 1400x900; real Electron deletion not tested. |
| UI-019 | Every statistics widget shall use the same title, collapse and vertical bottom-divider resizing controls as filter widgets. Heights shall persist independently across restarts and column or widget collapse. | Should | Implemented | D35: reuse D27/D34 helpers, styling and storage. Both shells passed pointer drags, keyboard resize/collapse and reload retention. Native Electron quit/relaunch not manually tested. |
| UI-020 | The filter and statistics columns shall have independently remembered collapsed states and keyboard-accessible icon toggles, consistent with the main menu. Narrow windows shall preserve usable results without overwriting the preferred wide-window layout. | Should | Implemented | D35: auto-hide statistics below 1200 px; opening either column takes priority when both cannot leave 420 px for results. Automatic hiding does not change saved preferences. Tests and browser layout checks passed at 960x600 and 1400x900 in both fonts; native resizing not manually tested. |
| UI-021 | The statistics sidebar shall be resizable in width using its left divider, with its initial width as the minimum. Its preferred width shall persist independently across restarts and collapse, and return after temporary viewport clamping. | Should | Implemented | D36: pointer-captured divider, Left/Right and Home/End keyboard resizing, independent statisticsW preference; 280 px minimum, up to 720 px within viewport/results bounds. All 23 renderer tests and browser drag, keyboard, collapse/reload and narrow/wide restoration checks passed in both fonts. Native Electron resizing and quit/relaunch retention not manually tested. |
| UI-022 | Background work (statistics/index builds, imports, dataset switching/creation/deletion, source removal, dataset statistics refresh) shall be shown in a notification area at the top of the application on every view. The area shall push content down instead of overlapping it. Running tasks shall show a progress bar (indeterminate when progress is unknown) and disappear when done; errors shall stay until dismissed with a close button. Several notifications shall stack. | Should | Implemented | D47. Renderer tests cover delay, in-place progress, done removal, stacking, keyed replacement and dismissal. Browser fixture verified layout push-down on list/settings/datasets at 1400x900 and 960x600, plus keyboard dismissal. 2026-10-29: explicit grid placement fixes shortened sidebars when notices are empty; 48 browser geometry cases passed across all four views, both sizes/fonts and empty/stacked/cleared notices. Native Electron start against an empty temporary config passed; native layout and real build/import/switch notices on the full DB not manually observed. |
| UI-023 | While filtered statistics are recalculated, the application shall show a top progress notification and cover each pending statistics widget, including the ads-over-time chart, with a dimmed overlay, an indeterminate loading indicator and "Refreshing statistics" text. Each overlay shall clear when its current request settles; the notification shall remain until result counts, facets and the chart have all settled. Superseded responses shall not clear current feedback. Widget collapse and resize controls and other filters shall remain usable. | Must | Implemented | D50: immediate per-widget overlays and shared UI-022 notice after 300 ms. Deferred-response tests cover independent completion, supersession, failures and building/stale replies. Browser fixture verified 1400x900/960x600 in both fonts, collapse, keyboard resize, Settings persistence and error dismissal. Disposable Electron startup passed; native full-dataset interaction not tested. |
| UI-024 | Themes shall be versioned JSON files defining all application colors through clearly named semantic tokens, including charts, dialogs, loading states, splash and window backgrounds. Themes shall not contain executable code, arbitrary CSS, remote assets or layout settings. | Must | Implemented | D51/D52: both complete built-in JSON files use the shared 65-token contract and two local font stacks. Contract, unsafe-input, consumer and bootstrap tests pass; native light/dark splash/main values verified. Custom file operations remain UI-027/UI-028. |
| UI-025 | Each theme shall define default and monospace font-family stacks. The existing monospace preference shall choose between them without being reset on theme changes; unavailable fonts shall use local fallbacks without network requests. | Must | Implemented | D51/D52: both built-ins supply validated local stacks with generic fallbacks. Browser verifies both modes, live switching and reload; native switching and quit/relaunch preserve the separate monospace preference. No remote font loading is enabled. |
| UI-026 | Theme shall be the first option in Settings > Appearance, with its label on the left and a current-theme name button on the right instead of a toggle. That button shall open a keyboard-accessible modal. Each theme shall have a selectable panel displaying its name and a small swatch in its own colors and fonts. Selection shall apply immediately without closing the modal or resetting application context. | Must | Implemented | User-revised placement, 2026-10-29; D54. Self-themed/fonted panels, swatches, check/pressed state, native buttons, busy/stale guards and restored focus implemented. Browser Enter/Space/Escape, background-navigation blocking, both sizes/themes/fonts and long/unavailable names pass. Native DOM-driven chooser/restart verified; physical native keyboard remains unverified. Settings caps at 450 px with a 30 px name button. |
| UI-027 | The theme modal shall support importing a JSON theme and provide separate download and trash icon actions on the right of each panel. Both built-ins shall be exportable but protected from deletion or replacement. Custom deletion shall require confirmation; deleting the active custom theme shall select ams-dark. | Must | Implemented | D53/D54: independent import/download/trash controls use validated IPC and in-app confirmations. Built-in deletion disabled and protected in main; unavailable entries remain removable. Unit/browser checks cover isolation, cancellation, failures, duplicate work, import/export and active fallback. Native confirmation/cancel/removal passes via DOM interaction. Actual OS Open/Save dialogs remain manually unverified. |
| UI-028 | Imported themes and the selected theme shall persist across application restarts independently of datasets. Invalid imports shall leave existing themes and selection unchanged and display an actionable error. Startup shall recover an unavailable or invalid selection with ams-dark and report the problem. | Must | Implemented | D52/D53: application-wide catalog and generated-ID copies persist independently of datasets. Bounded strict UTF-8/JSON validation, duplicate/reserved names, write rollback, corrupt-file isolation and crash recovery tested. Native custom startup, deletion fallback and restart verified with normal exits; actual native Open/Save interaction remains unverified. |
| UI-029 | A dedicated theming reference shall list every supported theme option and its effect. Adding, modifying or removing color or font tokens shall update the reference, validation contract, both default theme files and regression coverage together. Project agent instructions shall enforce this rule. | Must | Implemented | D51/D52: reference and both agent files enforce synchronized changes. Both defaults exist; tests verify matching complete token/font sets, shared validation and documented consumers. |
