# UI requirements (UI)

| ID | Requirement | Priority | Status | Notes |
|---|---|---|---|---|
| UI-001 | The application shall have a modern, sleek UI. | Must | Implemented | Not yet visually reviewed. |
| UI-002 | The application shall use a dark theme. | Must | Implemented | |
| UI-003 | The color scheme shall favor teal, blue, purple and pink. | Must | Implemented | CSS variables in `styles.css`. |
| UI-004 | Related information (location, occupation levels, etc.) shall be distinguishable by consistent tag colors. | Must | Implemented | See LST-002. |
| UI-005 | Updates shall not reload the page or reset the user's context. | Must | Implemented | |
| UI-006 | The window shall have a minimum usable size. | Could | Implemented | 960x600. |
| UI-007 | The filter sidebar shall be resizable in width, with its current width as the minimum. Its sections, titles and inputs shall not overlap at the minimum width or window size. | Should | Implemented | D27: non-shrinking sections scroll instead of overlapping. Browser fixture verified at 310 px, 960x600 and 1400x900, in both font modes; drag resizing and chart redraw passed. |
| UI-008 | The filter sidebar shall be collapsible and expandable so the list can use the full width. | Should | Implemented | Toggle button left of the search box; state saved. Not seen in the UI. |
| UI-009 | The main menu shall be collapsible to icons only, and shall be collapsed by default. | Should | Implemented | Toggle at the bottom of the menu (labels get tooltips); state saved. Not seen in the UI. |
| UI-010 | Filter boxes with hierarchical selection (occupation, location) shall be resizable up/down so more of the tree can be viewed vertically. | Should | Planned | Not started. See docs/tasks.md. |
| UI-011 | The filter widgets, including the ads-over-time chart, in the filter sidebar and the statistics widgets in the statistics bar shall each be collapsible and expandable by pressing their title, using a mouse or keyboard. Collapsed state shall persist across restarts; collapsed filter widgets shall indicate active selections. | Should | Implemented | D27: T2 complete for all six existing widgets; shared helper available for future T8/T9/T5 widgets. Unit tests and browser click/Enter/Space, reload persistence and active-filter badges passed. Actual Electron quit/relaunch persistence not manually tested. |
| UI-012 | The UI shall use monospace font(s) to give it the feel of a data inspection tool. | Should | Implemented | D26: all main-window text, including headings and ad descriptions, uses an offline system monospace stack by default. Browser fixture layout checked at 960x600 and 1400x900; Electron startup verified. |
| UI-013 | The search view shall have a statistics bar on its right-hand side for statistics widgets other than the ads-over-time chart, which shall stay in the filter column beside the time filters. The bar itself shall be collapsible, and each statistics widget shall be collapsible (UI-011). | Should | Planned | Hosts the map (SRC-019) and employers widget (SRC-020). T8 is independent of T2; see docs/tasks.md. |
| UI-014 | While the application starts and loads its data, a splash screen with a loading progress bar shall be shown, so it is clear that the application is starting. | Must | Implemented | Frameless splash window with stage text, percentage and elapsed time; closes when the main window has its first results. Layout not seen by the agent (window opened, not viewed). |
| UI-015 | Large ad counts in the UI shall use compact, human-readable notation, with exact counts available on hover. | Must | Implemented | D25: shared compact formatter (e.g. 12.5k, 11.3M); exact hover values in filters, totals, chart and import counts. Boundary tests and Electron startup verified; visual layout not reviewed. |
| UI-016 | Settings shall provide a monospace on/off option that applies immediately to all main-window text and persists across application restarts; monospace shall be enabled by default. | Must | Implemented | D26: Settings > Appearance slider-style switch; localStorage settings object. Unit tests and browser reload verified; actual Electron quit/relaunch preference retention not manually tested. |
| UI-017 | Each hierarchical filter box (occupation and location) shall provide a small text button labelled "collapse all" directly below its search field, usable by mouse or keyboard, that collapses every level in that tree without changing active filter selections or the other tree. | Must | Implemented | D30: text controls inside widget bodies, distinct from title-based widget collapse; clear only the target tree's search text and saved expansions. Renderer tests and earlier browser fixture click/Enter/Space, selection retention and reload persistence passed. Revised text/placement, non-overlap, collapse and hiding with the widget verified at 960x600; native Electron interaction not manually tested. |
| UI-018 | Application popup messages and confirmation queries shall use in-app modal dialogs matching the keyboard-shortcut help style instead of native alert/confirm popups. Removing a data source shall require explicit confirmation; Cancel or Escape shall leave it unchanged. Dialogs shall contain focus, block background navigation and restore focus on dismissal; destructive confirmations shall initially focus Cancel. | Must | Implemented | D33: shared dialog shell for shortcut help, source-removal confirmation and failure messages. Renderer tests and browser fixture interactions/layout passed at 960x600 and 1400x900; real Electron deletion not tested. |
