# Search and filter requirements (SRC)

| ID | Requirement | Priority | Status | Notes |
|---|---|---|---|---|
| SRC-001 | The user shall be able to filter on occupation field, occupation group and occupation. | Must | Implemented | Collapsible tree with counts; deepest selected level applies. |
| SRC-002 | The user shall be able to filter on location (region and municipality). | Must | Implemented | Tree with counts. |
| SRC-003 | The user shall be able to search by keyword. | Must | Implemented | Headline, employer, description; phrases in quotes; prefix matching. |
| SRC-004 | The user shall be able to filter by publication date range. | Must | Implemented | From/to date inputs. |
| SRC-005 | The user shall be able to filter by year with one click. | Should | Implemented | Year chips with counts. |
| SRC-006 | The user shall be able to filter by employment type. | Should | Implemented | |
| SRC-007 | The user shall be able to filter by working hours. | Should | Implemented | |
| SRC-008 | The list shall update dynamically as filters change, without reloading the page. | Must | Implemented | The free-text box is the exception (SRC-021): it applies on Enter. |
| SRC-009 | Filter options shall show counts reflecting the other active filters. | Should | Implemented | Own-filter excluded per group. D25: normalize missing-value merge keys and sum duplicate groups; hide stale counts while loading. Tests cover every dimension, mixed NULL/empty values, refresh completion, stale responses and error logging; real-data query matched all facet totals (9,100 ads). Reported startup placeholders were not reproduced in a fresh native instance (2026-10-16); original cause remains unconfirmed. |
| SRC-010 | Active filters shall be shown as removable chips, with a "Clear all" action. | Should | Implemented | |
| SRC-011 | The user shall be able to sort by newest, oldest and (with keyword) relevance. | Should | Implemented | |
| SRC-012 | The occupation and location trees shall be searchable by text. | Could | Implemented | |
| SRC-013 | Filters shall be remembered when opening an ad and returning to the list, for as long as the application is open; they need not be remembered between sessions. | Must | Implemented | Kept in memory and `sessionStorage`; a new start begins with no filters. Changed 2026-10-15 (a stale saved keyword filter made starting slow). |
| SRC-014 | Every multi-layer filter (occupation: field/group/occupation; location: region/municipality; and any added later) shall support multiple selections on each level. Selecting a narrower item shall deselect its wider ancestors only; selections in other branches shall remain. | Must | Implemented | Selections are OR-combined per filter. Selecting a wider item drops its narrower descendants (redundant). Verified by code and DB queries; UI not seen. |
| SRC-015 | Filter options shall not change due to filtering: all available options remain visible even if no filtered ad matches. Each option shall still show its ad count (0 if none) and remain selectable, with grayed-out text signalling that selecting it will not affect the current view. | Must | Implemented | Applies to occupation and location trees, year, employment and working-hours chips. Counts exclude the option's own filter (SRC-009). Verified by DB queries; gray styling not seen. |
| SRC-016 | The free-text search shall support multiple free-text entries. Typing text and pressing Enter shall add it as a free-text filter, displayed as a box with an "X" inside the search input (like the other filter chips) to show it is applied. The "X" shall remove the entry; Backspace with the cursor directly after the last box shall also remove it. | Must | Implemented | Entries are combined with AND (default) or OR (SRC-018); text being typed does not filter until Enter (SRC-021). Verified by DB query and syntax check; UI interaction not seen. |
| SRC-017 | In the filter column beside the publication-date filters there shall be a line graph of the number of ads published across the selected time period (the date filter, or the whole data range when none is set), reflecting the other active filters. The axis labelling and bin size shall adapt to the span: years for many years; years (at January) and months for a few years; months for about one year; months (at the first of the month) and weeks for a few months; down to individual days for short spans. | Should | Implemented | D27: chart stays at the top of the filter sidebar. Bins: year > ~6 y, month 150 days to 6 y, week 45 to 150 days, day otherwise. Hover shows the count per bin. Counts previously verified by DB queries (sums match); browser fixture verified yearly labels, collapse/expand and resize at 310 px. Other bin-span layouts not visually reviewed. |
| SRC-018 | The free-text search bar shall have a button on its right side, inside the text field, to choose whether the entries are combined with "AND" (all must match) or "OR" (any may match). | Must | Implemented | Default AND; choice saved with the filters. Each entry is a unit (its own words are AND-ed). Verified by DB queries (`sjuksköterska` 8,675, `hemtjänst` 2,594: AND 674, OR 10,595); button not seen in the UI. |
| SRC-019 | In the statistics bar (UI-013) there shall be a geographical view with a hotspot overlay (or similar) showing where the filtered ads are located. | Should | Planned | Not started. Timeline stays in the filter column (SRC-017). Open questions on coordinates and map base in docs/tasks.md. |
| SRC-020 | A statistics widget shall show the names of the employers (companies) as labels, ordered from most to least frequent among the filtered ads, limited to the top 30. | Should | Planned | Not started. Each label shows its ad count. Employer name variants and a click-to-filter behavior are open; see docs/tasks.md. |
| SRC-021 | The free-text search (including its prefix/wildcard matching) shall not refresh the list or the filters for every typed character. It applies only when Enter is pressed and a new, definitive entry has been added. | Must | Implemented | Replaces the earlier live-while-typing behavior (see SRC-008, SRC-016). Text left in the box is not part of the filter. Old saved live text is kept as an entry on load. Syntax-checked only; UI not seen. |
