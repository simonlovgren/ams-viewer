# Data requirements (DAT)

| ID | Requirement | Priority | Status | Notes |
|---|---|---|---|---|
| DAT-001 | The application shall use historical job ad data in JobTech JSONL format (one ad per line) as its source. | Must | Implemented | Reference file: `2026-Q3.jsonl`. |
| DAT-002 | It shall be easy to add more source files; files for 2006–2026 are expected over time. | Must | Implemented | Via Data sources view. |
| DAT-003 | The application shall import data into an embedded local database rather than use the files as-is. | Must | Implemented | One SQLite database per named dataset under `~/.config/AMS Viewer/datasets/`; catalog in `datasets.json` (D39). |
| DAT-004 | The import feature shall accept multiple files in one operation. | Must | Implemented | File picker multi-select and drag & drop. |
| DAT-005 | The importer shall accept `.jsonl`, `.ndjson` and `.json` (array) files of any size. | Should | Implemented | Array files are streamed (511 MB single-line array: 100k ads in 29 s, peak RSS 146 MB). |
| DAT-006 | Import shall not block the UI and shall show progress (file x of n, added, duplicates, errors). | Must | Implemented | Worker thread. |
| DAT-007 | Ads already stored (same ad id) shall be skipped on import, so files may be re-imported or overlap. | Must | Implemented | |
| DAT-008 | Invalid records shall be counted and skipped without aborting the import. | Must | Implemented | Lines are split on `\n` only; U+2028/2029 occur inside texts. |
| DAT-009 | The user shall be able to see imported sources with ad counts and remove a source with its ads. | Should | Implemented | D33 / UI-018: themed confirmation defaults to Cancel; removal failures use the same modal. Original source files are not deleted. Browser fixture verified; real Electron deletion not tested. |
| DAT-010 | The application shall show total ad count, number of sources and year range covered. | Could | Implemented | |
| DAT-011 | If the database is empty at startup, the application shall open the Data sources view. | Could | Implemented | |
| DAT-012 | The importer shall handle all generations of the source data (2006–2026): ads without an id, numeric ids, array-valued taxonomy fields, `.jsonl` and `.json` array files, and both date formats. | Must | Implemented | Verified on samples of every file and full imports of `2018.json` (3.6 GB array, 683k ads, 188 s, peak RSS 210 MB) and `2006.jsonl` (243k ads, 34 s). Remaining files not fully imported yet. |
| DAT-013 | The Data sources page shall update the imported-files list while an import runs and when it finishes, without reloading the view. | Should | Planned | Not started. Today the list is re-rendered only on completion and only if the view is open. See docs/tasks.md. |
| DAT-014 | For each imported file the Data sources list shall show the elapsed import time, the number of duplicates and the number of errors. | Should | Planned | Not started. Needs these values stored per source. See docs/tasks.md. |
| DAT-015 | The application shall enrich missing occupation information in older ads by cross-referencing `legacy_taxonomy_id` with the newest available dataset containing a reliable mapping, so resolved information is displayed and filterable like that of newer ads. | Should | Planned | T12. Survey other legacy taxonomy fields for the same approach. Preserve existing values; leave ambiguous or unmatched values unresolved. |
| DAT-016 | The application shall enrich missing location information in older ads by cross-referencing available `workplace_address` fields with the newest available dataset containing a reliable geographic mapping, so resolved information is displayed and filterable like that of newer ads. | Should | Planned | T12. Verify field coverage and historical geographic changes; preserve existing values and leave ambiguous or unmatched values unresolved. |
| DAT-017 | The application shall support multiple named datasets, each backed by a separate database, and allow switching the active dataset so search, filters, statistics and source management operate only on that dataset. | Must | In progress | T15 adds isolated DBs, persisted activation, worker routing and lifecycle IPC (D39). T17 still needs chooser UI and renderer refresh/state handling. |
| DAT-018 | The application shall initially provide a dataset named exactly "default", allow dataset deletion, and recreate and activate an empty dataset named "default" if every dataset is deleted. | Must | In progress | T15 adds default creation, deletion IPC, oldest-remaining fallback and empty-default recreation (D39). T17 still needs deletion entry point and confirmation UI. |
| DAT-019 | The Data sources view and its navigation entry shall be renamed "Datasets", retaining the existing overall design and source-management functionality within the active dataset; the page heading shall display the active dataset's name. | Must | Planned | T16. Planned rename also applies to the view referenced by DAT-002, DAT-011, DAT-013 and DAT-014; existing implementation remains unchanged until this work is done. |
| DAT-020 | The dataset heading shall have adjacent Edit and Swap dataset buttons. Edit shall enter an editable state with Save and Discard buttons; clicking the heading itself shall enter the same state and automatically select the name text for editing. Save shall persist changes and Discard shall leave stored values unchanged. | Must | Planned | T16. Verify heading-click text selection separately from Edit-button activation. |
| DAT-021 | Creating a dataset shall start in edit mode with the name field focused and its text selected, ready for input; saving an unnamed or whitespace-only dataset shall be rejected. | Must | In progress | T15 persists only trimmed, nonblank names; T16 still needs creation editor/focus behavior (D39). |
| DAT-022 | Each dataset shall support an optional multiline description editable in a multiline text box and saved or discarded together with its name. | Must | In progress | T15 persists multiline descriptions with metadata; T16 still needs editor/save/discard UI (D39). |
| DAT-023 | Swap dataset shall open a compact, selectable list of existing datasets, with "+ add new dataset" as the final option; selecting a dataset shall activate it, and selecting the final option shall start dataset creation. | Must | Planned | T17. Keep the chooser consistent with the existing UI. |
| DAT-024 | Each dataset entry in the chooser shall show its name, the first line of its description when present, and dataset statistics including imported-file count and total ad count. | Must | Planned | T17. Additional statistics may reuse the existing year-range summary. |
