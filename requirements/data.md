# Data requirements (DAT)

| ID | Requirement | Priority | Status | Notes |
|---|---|---|---|---|
| DAT-001 | The application shall use historical job ad data in JobTech JSONL format (one ad per line) as its source. | Must | Implemented | Reference file: `2026-Q3.jsonl`. |
| DAT-002 | It shall be easy to add more source files; files for 2006–2026 are expected over time. | Must | Implemented | Via Datasets view. |
| DAT-003 | The application shall import data into an embedded local database rather than use the files as-is. | Must | Implemented | One SQLite database per named dataset under `~/.config/AMS Viewer/datasets/`; catalog in `datasets.json` (D39). |
| DAT-004 | The import feature shall accept multiple files in one operation. | Must | Implemented | File picker multi-select and drag & drop. |
| DAT-005 | The importer shall accept `.jsonl`, `.ndjson` and `.json` (array) files of any size. | Should | Implemented | Array files are streamed (511 MB single-line array: 100k ads in 29 s, peak RSS 146 MB). |
| DAT-006 | Import shall not block the UI and shall show progress (file x of n, added, duplicates, errors). | Must | Implemented | Worker thread. |
| DAT-007 | Ads already stored (same ad id) shall be skipped on import, so files may be re-imported or overlap. | Must | Implemented | |
| DAT-008 | Invalid records shall be counted and skipped without aborting the import. | Must | Implemented | Lines are split on `\n` only; U+2028/2029 occur inside texts. |
| DAT-009 | The user shall be able to see imported sources with ad counts and remove a source with its ads. | Should | Implemented | D33 / UI-018: themed confirmation defaults to Cancel; removal failures use the same modal. Original source files are not deleted. Browser fixture verified; real Electron deletion not tested. |
| DAT-010 | The application shall show total ad count, number of sources and year range covered. | Could | Implemented | |
| DAT-011 | If the database is empty at startup, the application shall open the Datasets view. | Could | Implemented | |
| DAT-012 | The importer shall handle all generations of the source data (2006–2026): ads without an id, numeric ids, array-valued taxonomy fields, `.jsonl` and `.json` array files, and both date formats. | Must | Implemented | D20 import normalization; D48 repairs missing promoted array-valued taxonomy, employment and hours from stored JSON once per dataset, without re-import. Regression tests cover listing/filter/summary consistency and interrupted repair; full-scale migration and native listing remain unverified. |
| DAT-013 | The Datasets page shall update the imported-files list while an import runs and when it finishes, without reloading the view. | Should | Planned | Not started. Today the list is re-rendered only on completion and only if the view is open. See docs/tasks.md. |
| DAT-014 | For each imported file the Datasets list shall show the elapsed import time, the number of duplicates and the number of errors. | Should | Planned | Not started. Needs these values stored per source. See docs/tasks.md. |
| DAT-015 | The application shall enrich missing occupation information in older ads by cross-referencing `occupation.legacy_ams_taxonomy_id` with the newest available dataset containing a reliable mapping, so resolved information is displayed and filterable like that of newer ads. | Should | Implemented | T12/D58: dataset-local complete-tuple consensus is backfilled and maintained on import, source removal and reprocessing. Worker/DB regression suite and disposable Electron startup pass. Q3 survey maps 4,038,404 of 4,667,640 ads from 2007–2017; full-scale migration runtime remains unmeasured. |
| DAT-016 | The application shall enrich missing location information in older ads by cross-referencing available `workplace_address` fields with the newest available dataset containing a reliable geographic mapping, so resolved information is displayed and filterable like that of newer ads. | Should | Implemented | T12/D58: dataset-local municipality and region consensus is maintained independently and only fills source-missing values. Worker/DB regression suite and disposable Electron startup pass. Q3 survey maps 4,573,278 of 4,606,062 coded ads from 2007–2017 to a municipality; full-scale migration runtime remains unmeasured. |
| DAT-017 | The application shall support multiple named datasets, each backed by a separate database, and allow switching the active dataset so search, filters, statistics and source management operate only on that dataset. | Must | Implemented | T15/D39 storage and worker lifecycle; T17/D42 chooser, state refresh, history boundary and failure recovery. Renderer filters reset on switch. |
| DAT-018 | The application shall initially provide a dataset named exactly "default", allow dataset deletion, and recreate and activate an empty dataset named "default" if every dataset is deleted. | Must | Implemented | T15/D39 lifecycle IPC; T17/D42 adds deletion confirmation and replacement refresh. |
| DAT-019 | The Data sources view and its navigation entry shall be renamed "Datasets", retaining the existing overall design and source-management functionality within the active dataset; the page heading shall display the active dataset's name. | Must | Implemented | T16/D40; renderer tests and 960×600 / 1400×900 browser layout checks passed. |
| DAT-020 | The dataset heading shall have adjacent Edit and Swap dataset buttons. Edit shall enter an editable state with Save and Discard buttons; clicking the heading itself shall enter the same state and automatically select the name text for editing. Save shall persist changes and Discard shall leave stored values unchanged. | Must | Implemented | T16/D40/D41 inline metadata editor; T17/D42 connects Swap to chooser. |
| DAT-021 | Creating a dataset shall start in edit mode with the name field focused and its text selected, ready for input; saving an unnamed or whitespace-only dataset shall be rejected. | Must | Implemented | T16 editor is entered by T17 chooser's final add action; blank names rejected in renderer and catalog (D39/D42). |
| DAT-022 | Each dataset shall support an optional multiline description editable in place as the displayed CSS-styled text, together with its name in the styled heading, and saved or discarded together with its name. | Must | Implemented | T16/D40/D41 inline plain-text editor preserves displayed typography and line breaks. |
| DAT-023 | Swap dataset shall open a compact, selectable list of existing datasets, with "+ add new dataset" as the final option; selecting a dataset shall activate it, and selecting the final option shall start dataset creation. | Must | Implemented | T17/D42 native dialog; buttons support keyboard activation and Escape dismissal. |
| DAT-024 | Each dataset entry in the chooser shall show its name, the first line of its description when present, and dataset statistics including imported-file count and total ad count. | Must | Implemented | T17/D42 uses persisted source metadata snapshots; unknown legacy snapshots backfill through a read worker. |
| DAT-025 | The user shall be able to manually report an individual ad as erroneous and exclude it from the active dataset's browsable ads, search results, filters, counts and statistics. Suspect dates alone shall not trigger silent exclusion during import. | Should | Planned | T18. User-reported example: ads dated 2099. Exclusion is an explicit local action, not an upstream report; original source files remain unchanged. |
| DAT-026 | The Datasets view shall provide a manual action to reprocess the active dataset's stored ads and rebuild all derived statistics, search indexes and other imported projections without requiring the original source files. It shall require modal confirmation warning that processing may take a long time and show progress in the application-wide top notification area. Failed processing shall also show a dismissible error status notification. | Must | Implemented | D49; UI-018 confirmation and UI-022 progress/errors. All 68 tests, syntax/editor checks and disposable Electron startup pass. Browser fixture verifies modal and injected progress/error notices at 960x600 and 1400x900. Native rebuild interaction and full-scale runtime/disk usage unverified. |
